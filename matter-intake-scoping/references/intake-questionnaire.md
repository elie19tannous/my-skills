# Intake Questionnaire (Interview Script & File-Opening Checklist)

Use this as the live interview script for a new matter and as the checklist before a file is opened. Every mandatory field must be filled or explicitly marked as an open item to request — never guessed.

## A. Client & Instruction
- [ ] Client full legal name (+ trading name / alias)
- [ ] Client type: individual / company / partnership / public body / trust
- [ ] Contact & authorised instructing person (and their authority to instruct)
- [ ] How the client found the firm / referral source
- [ ] Client's goal in their own words (success criteria)
- [ ] Matter type (dispute / transactional / advisory / family / regulatory / other)
- [ ] Urgency and any date already known to be critical

## B. Facts & Chronology
- [ ] Neutral dated chronology — one atomic event per line (YYYY-MM-DD — event)
- [ ] Facts separated from the client's characterizations/conclusions (label which is which)
- [ ] Documents held vs documents needed (open-items list)
- [ ] Amounts in issue / value of the matter
- [ ] What is NOT yet known (unconfirmed dates, unnamed parties, missing docs)

## C. Parties (one row each — feeds the conflicts search)
For every party the matter touches, not just the two obvious sides:
- Legal name (+ alias/trading name)
- Type (individual / company / partnership / public body / trust)
- Role (client / adverse party / co-defendant / witness / insurer / guarantor / related entity)
- Relationship to client and to other parties
- Identifiers (company/registration number, ID where lawfully held)

Prompt explicitly for the hidden parties: parent companies, subsidiaries, directors, shareholders, spouses, guarantors, insurers, funders.

## D. Conflicts Targets
- [ ] Full list of every party + related entity to search (from section C)
- [ ] Search status per party: not searched / clear / positive / potential / business
- [ ] Any known prior relationship with any party (prior client, prior adverse)
- [ ] Escalation note where a positive/potential/business conflict is flagged
> Status is "pending" until each party is run against the firm's actual client-matter records. Never record "clear" from memory.

## E. Deadlines & Limitation
- [ ] Limitation / prescription date — rule, trigger date, computed drop-dead date (HIGH risk if unknown/contested)
- [ ] Contractual deadlines (notice, cure, option, renewal, response windows)
- [ ] Procedural deadlines (filing, service, response, appeal) if litigation is live
- [ ] Regulatory/statutory windows
- [ ] Each deadline diaried with a lead-time reminder

## F. Scope (drives the fee)
- [ ] In scope — deliverables/phases
- [ ] Out of scope — explicit exclusions
- [ ] Assumptions the scope relies on
- [ ] Client dependencies (documents/decisions/approvals needed and when)

## G. Fee & Commercials
- [ ] Fee basis (fixed / hourly / capped / phased / contingency, per local rules)
- [ ] Build-up (hours × rate by phase/fee-earner, or fixed-fee rationale)
- [ ] Disbursements listed separately
- [ ] Tax (VAT/sales tax) shown separately
- [ ] Estimate vs quote/fixed fee stated explicitly
- [ ] Range + drivers where uncertain
- [ ] Retainer / money-on-account requirement
- [ ] AML/KYC / identity verification requirement noted where applicable

## H. Recommendation
- [ ] Open / decline / hold, with conditions (conflict waiver, limitation resolved, retainer received)

## Mandatory-to-open (blockers if empty)
client name • at least client + primary adverse party • conflicts status for every party • limitation date (or explicit "none / N/A with reason") • scope-in • scope-out • fee basis • open/decline/hold recommendation
